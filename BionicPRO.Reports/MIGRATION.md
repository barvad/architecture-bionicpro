# Миграция архитектуры отчётов

## Старая архитектура

```
Client
  ?
API ReportsController
  ?
ClickHouse
  ?
UserReport[] (полные данные в памяти)
  ?
JSON response (большой размер)
```

**Проблемы:**
- Полные данные отчётов отправляются каждый раз
- Нет кеширования
- Нагрузка на API при каждом запросе
- Большой трафик

## Новая архитектура

```
Client
  ?
API ReportsController (с авторизацией)
  ?
ReportService (логика обработки)
  ?? ClickHouse (получение данных)
  ?? MinioService (проверка/загрузка)
  ?? MinIO S3 (хранилище)
        ?
   Nginx CDN (кеширование)
        ?
   Client получает URL ? скачивает из CDN
```

**Улучшения:**
- URL-based delivery (лёгкий ответ)
- Кеширование на 30 минут
- Меньше трафика между API и клиентом
- Масштабируемость
- Версионирование файлов

## Что изменилось

### 1. API Response

**Старая версия:**
```json
[
  {
    "userId": "...",
    "reportDate": "2024-01-15T00:00:00Z",
    "fullName": "John Doe",
    "prostheticModel": "...",
    "stepsCount": 12345,
    "avgBatteryLevel": 85.5,
    "errorsCount": 2
  }
]
```

**Новая версия:**
```json
[
  {
    "reportDate": "2024-01-15T00:00:00Z",
    "reportUrl": "http://localhost:8080/reports/.../2024/01/15.json",
    "status": "generated"
  }
]
```

### 2. Хранение данных

**Старая версия:**
- Данные только в памяти/кеше базы
- Нет долгосрочного хранилища

**Новая версия:**
- Отчёты сохраняются в MinIO
- Структурированное хранилище
- Возможность версионирования
- S3-compatible API

### 3. Доступ к отчётам

**Старая версия:**
- Только через API
- Каждый запрос требует авторизации

**Новая версия:**
- Через CDN URL
- Nginx кеширует
- Анонимный доступ к файлам (если не требуется)

## Migration Steps

### Step 1: Обновить конфигурацию
- Добавить MinIO параметры в `appsettings.json`
- Добавить ClickHouse connection string
- Добавить Keycloak Authority

### Step 2: Запустить сервисы
```bash
docker-compose -f docker-compose-cdn.yml up -d
```

### Step 3: Проверить бакет MinIO
```bash
# Должен быть создан бакет 'reports'
# С политикой анонимного доступа для чтения
```

### Step 4: Обновить клиент
- Вместо парсинга большого JSON
- Скачивать файлы по URL из ответа

### Step 5: Мониторинг
- Проверить логи API
- Проверить метрики MinIO
- Проверить кеш Nginx

## Rollback

Если нужно вернуться на старую архитектуру:

1. Остановить Minio и Nginx
```bash
docker-compose -f docker-compose-cdn.yml down
```

2. Вернуть старый ReportsController
3. Перестартовать API

## Performance Comparison

### Размер ответа
- **Старая**: 500KB-1MB (полные отчёты)
- **Новая**: ~1-2KB (только URLs)

### Время отклика (первый запрос)
- **Старая**: ~50-100ms
- **Новая**: ~100-150ms (+ сохранение в MinIO)

### Время отклика (последующие)
- **Старая**: ~50-100ms (всегда одинаково)
- **Новая**: ~10-20ms (из Nginx кеша)

### Трафик между API и клиентом
- **Старая**: ~500KB за запрос
- **Новая**: ~2KB за запрос (250x меньше)

## Pricing & Costs

### Преимущества
- ? Меньше пропускной способности

- ? Масштабируемость
- ? Долгосрочное хранение
